# 并发事务问题

并发事务是多个事务在相近时间内同时操作数据库。并发可以提高系统处理能力，但如果缺少合适的隔离机制，可能出现脏读、不可重复读和幻读。

| 问题 | 核心表现 |
| --- | --- |
| 脏读 | 读到了其他事务尚未提交的数据 |
| 不可重复读 | 同一事务两次读取同一行，字段值不同 |
| 幻读 | 同一事务两次执行相同条件查询，得到的记录集合不同 |

## 1. 脏读

脏读是一个事务读取了另一个事务尚未提交的修改。

| 时刻 | 事务A | 事务B |
| --- | --- | --- |
| 1 | 开启事务，将余额从2000修改为1000 | 开启事务 |
| 2 | 尚未提交 | 读取到余额为1000 |
| 3 | 执行`ROLLBACK`，余额恢复为2000 | 已经使用了无效的1000 |

事务B读取的1000最终被事务A回滚，因此这次读取的数据不可靠，就像读取了“脏数据”。

## 2. 不可重复读

不可重复读是同一个事务先后读取同一行记录，但两次读到的字段值不同。通常是因为另一个事务在两次读取之间修改或删除了该记录并提交。

| 时刻 | 事务A | 事务B |
| --- | --- | --- |
| 1 | 读取某员工工资，结果为8000 |  |
| 2 |  | 将该员工工资修改为9000并提交 |
| 3 | 再次读取同一名员工，结果为9000 |  |

事务A没有修改数据，却无法重复得到第一次读取的结果，因此称为不可重复读。

## 3. 幻读

幻读是同一个事务先后执行相同的条件查询，但两次得到的记录集合不同。通常是因为另一个事务在两次查询之间插入或删除了符合条件的记录并提交。

| 时刻 | 事务A | 事务B |
| --- | --- | --- |
| 1 | 查询部门编号为1的员工，得到3条记录 |  |
| 2 |  | 插入一名部门编号为1的员工并提交 |
| 3 | 再次执行相同查询，得到4条记录 |  |

第二次查询像是突然多出了一条原来不存在的记录，因此称为幻读。

## 4. 不可重复读与幻读的区别

| 对比项 | 不可重复读 | 幻读 |
| --- | --- | --- |
| 关注对象 | 同一行记录的字段值 | 满足条件的记录集合 |
| 常见原因 | 其他事务更新或删除记录并提交 | 其他事务插入或删除符合条件的记录并提交 |
| 结果表现 | 同一行前后读取的值不同 | 相同查询前后得到的记录数量或集合不同 |

简单理解：不可重复读侧重“原来的行变了”，幻读侧重“符合条件的行变多或变少了”。

## 5. 与事务隔离的关系

数据库通过事务隔离级别控制并发事务之间可以看到哪些数据。隔离级别越严格，能够避免的并发问题通常越多，但并发效率也可能受到更大影响。
