# 事务四大特性

事务具有原子性、一致性、隔离性和持久性，四个英文单词的首字母组合为`ACID`。

| 特性 | 英文 | 核心含义 |
| --- | --- | --- |
| 原子性 | Atomicity | 一组操作要么全部成功，要么全部撤销 |
| 一致性 | Consistency | 事务执行前后，数据都应满足约束和业务规则 |
| 隔离性 | Isolation | 并发事务之间应避免产生不符合隔离级别要求的相互干扰 |
| 持久性 | Durability | 事务提交后，修改结果应被永久保存 |

## 1. 原子性（Atomicity）

原子性表示事务是一个不可分割的工作单元，事务中的操作要么全部成功，要么全部失败并撤销。

例如，张三向李四转账1000元：

1. 张三的余额减少1000元。
2. 李四的余额增加1000元。

如果第二步失败，第一步也必须回滚，不能只扣除张三的钱。

`COMMIT`用于确认事务成功，`ROLLBACK`用于撤销当前事务中尚未提交的修改。

## 2. 一致性（Consistency）

一致性表示事务执行前和执行后，数据库都应处于符合数据约束和业务规则的有效状态。

例如，转账前后两人的资金总额不应凭空增加或减少，账户余额也应满足系统规定的业务规则。

一致性不仅依靠数据库本身，还需要共同保证：

- 主键、外键、唯一、检查等数据库约束。
- 事务的原子性、隔离性和持久性。
- 应用程序中正确的业务逻辑。

## 3. 隔离性（Isolation）

隔离性用于控制多个事务同时执行时相互看到和影响数据的程度，使每个事务都能在符合隔离级别要求的环境中运行。

例如，转账尚未提交时，其他事务不应随意读取并使用不完整的中间状态。

隔离并不表示所有事务在任何情况下都完全互不影响。数据库通过不同的事务隔离级别，在数据一致性和并发效率之间进行取舍。

## 4. 持久性（Durability）

持久性表示事务一旦通过`COMMIT`成功提交，修改结果就应被永久保存。即使数据库发生异常或服务器重启，也应能够通过存储和恢复机制保留已经提交的数据。

`ROLLBACK`表示放弃尚未提交的修改，因此被回滚的修改不会永久保存。持久性针对的是成功提交的事务，不是被回滚的事务。

## 5. 使用转账理解ACID

| 特性 | 在转账中的表现 |
| --- | --- |
| 原子性 | 扣款和收款必须同时成功或同时撤销 |
| 一致性 | 转账前后资金总额和账户规则保持正确 |
| 隔离性 | 并发操作不能错误使用转账过程中的中间状态 |
| 持久性 | 转账提交后，即使系统重启，结果仍然存在 |
