# 事务概述与操作

事务（Transaction）是一组数据库操作组成的不可分割工作单元。这组操作要么全部成功并提交，要么在出现问题时全部撤销。

例如，张三向李四转账1000元，需要完成两个操作：

1. 张三的余额减少1000元。
2. 李四的余额增加1000元。

如果只完成其中一个操作，数据就会出现错误，因此需要把它们放进同一个事务。

## 1. MySQL的自动提交

MySQL默认开启自动提交。每条成功执行的SQL语句都会形成一个独立事务，并在语句结束后自动提交。

查看当前会话的自动提交状态：

```sql
SELECT @@autocommit;
```

查询结果说明：

| 结果 | 含义 |
| --- | --- |
| `1` | 开启自动提交 |
| `0` | 关闭自动提交，需要手动提交或回滚 |

## 2. 手动事务的两种方式

### 2.1 方式一：关闭自动提交

关闭当前数据库连接的自动提交：

```sql
SET autocommit = 0;
```

关闭后，从下一条事务语句开始，后续操作属于当前事务，直到执行`COMMIT`或`ROLLBACK`。

```sql
SET autocommit = 0;

UPDATE account
SET money = money - 1000
WHERE name = '张三';

UPDATE account
SET money = money + 1000
WHERE name = '李四';

COMMIT;
```

`COMMIT`或`ROLLBACK`结束当前事务后，只要`autocommit`仍为`0`，下一条事务语句又会开始一个新事务。

使用完毕后，可以重新开启自动提交：

```sql
SET autocommit = 1;
```

重新开启前，应先明确执行`COMMIT`或`ROLLBACK`，避免意外提交尚未处理的修改。

### 2.2 方式二：显式开启事务

保持自动提交开启，使用下面任意一条语句显式开启当前事务：

```sql
START TRANSACTION;
```

或者：

```sql
BEGIN;
```

完整转账示例：

```sql
START TRANSACTION;

UPDATE account
SET money = money - 1000
WHERE name = '张三';

UPDATE account
SET money = money + 1000
WHERE name = '李四';

COMMIT;
```

`START TRANSACTION`和`BEGIN`作用相同，只需要选择其中一种。执行`COMMIT`或`ROLLBACK`后，这次显式事务结束；如果自动提交原本开启，后续语句继续自动提交。

## 3. 提交与回滚

### 3.1 提交事务

```sql
COMMIT;
```

`COMMIT`将当前事务中的修改永久保存。

### 3.2 回滚事务

```sql
ROLLBACK;
```

`ROLLBACK`撤销当前事务中尚未提交的修改。如果转账过程中出现异常，应执行回滚：

```sql
START TRANSACTION;

UPDATE account
SET money = money - 1000
WHERE name = '张三';

UPDATE account
SET money = money + 1000
WHERE name = '李四';

ROLLBACK;
```

已经通过`COMMIT`提交的修改不能再使用普通`ROLLBACK`撤销。

## 4. 两种方式的区别

| 方式 | 开启方法 | 影响范围 | 结束后的状态 |
| --- | --- | --- | --- |
| 关闭自动提交 | `SET autocommit = 0` | 当前数据库连接持续使用手动提交 | `COMMIT`或`ROLLBACK`后，下一条事务语句开始新事务 |
| 显式开启事务 | `START TRANSACTION`或`BEGIN` | 只控制当前这一次事务 | 事务结束后恢复原来的自动提交行为 |

一般需要临时执行一组事务操作时，使用`START TRANSACTION`更直观；需要当前连接持续手动控制事务时，可以关闭自动提交。

## 5. 使用注意

- 事务主要用于把多条有关联的`INSERT`、`UPDATE`和`DELETE`操作作为一个整体处理。
- 示例依赖支持事务的存储引擎，例如InnoDB；不支持事务的存储引擎无法正常回滚数据。
- `CREATE TABLE`、`ALTER TABLE`、`DROP TABLE`和`TRUNCATE TABLE`等DDL语句可能产生隐式提交，不能把它们当作普通DML操作进行回滚。
- `SET autocommit`只影响当前数据库连接，不会永久修改所有连接的设置。
