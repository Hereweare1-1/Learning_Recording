# 事务隔离级别

事务隔离级别用于规定并发事务之间能够看到哪些数据，从而在数据一致性和并发性能之间进行取舍。

> [!tip] 记忆规律
> 从上到下，隔离级别越高，数据越安全，性能越差。

这句话表示一种总体趋势：隔离级别越高，能够避免的并发事务问题越多，但事务之间的等待和系统开销通常也会增加。实际性能还会受到SQL语句、索引、数据量和并发量等因素影响。

## 1. 四种事务隔离级别

下表是SQL标准下的常见对照。“可能发生”表示该隔离级别不能保证避免这个问题，“不会发生”表示能够避免这个问题。

| 隔离级别 | 脏读 | 不可重复读 | 幻读 |
| --- | --- | --- | --- |
| `READ UNCOMMITTED`（读未提交） | 可能发生 | 可能发生 | 可能发生 |
| `READ COMMITTED`（读已提交） | 不会发生 | 可能发生 | 可能发生 |
| `REPEATABLE READ`（可重复读） | 不会发生 | 不会发生 | 可能发生 |
| `SERIALIZABLE`（串行化） | 不会发生 | 不会发生 | 不会发生 |

### 1.1 READ UNCOMMITTED

可以读取其他事务尚未提交的数据，并发性能较高，但可能出现脏读、不可重复读和幻读，数据可靠性最低。

### 1.2 READ COMMITTED

只能读取其他事务已经提交的数据，因此可以避免脏读，但仍可能出现不可重复读和幻读。

### 1.3 REPEATABLE READ

同一个事务多次读取同一条记录时，能够保持结果一致，因此可以避免脏读和不可重复读。

MySQL的InnoDB存储引擎默认使用该隔离级别。InnoDB还会通过一致性读和间隙锁等机制处理幻读问题，因此实际表现比上面的SQL标准对照更强。

### 1.4 SERIALIZABLE

隔离级别最高。它使用更严格的并发控制，使并发执行的结果等同于事务按顺序执行，可以避免脏读、不可重复读和幻读，但更容易出现等待，并发能力通常最低。

## 2. 查看事务隔离级别

查看当前会话的事务隔离级别：

```sql
SELECT @@transaction_isolation;
```

查看全局事务隔离级别：

```sql
SELECT @@global.transaction_isolation;
```

## 3. 设置事务隔离级别

### 3.1 设置当前会话

以下设置会影响当前连接后续开启的事务：

```sql
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
```

### 3.2 设置全局级别

以下设置会影响之后新建立的连接，不会改变已经存在的连接：

```sql
SET GLOBAL TRANSACTION ISOLATION LEVEL REPEATABLE READ;
```

设置全局级别通常需要相应的管理权限。

### 3.3 只设置下一个事务

省略`SESSION`和`GLOBAL`时，只为当前会话的下一个事务指定隔离级别。这条语句需要在事务开始之前执行：

```sql
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;
```

可选的隔离级别如下：

```text
READ UNCOMMITTED
READ COMMITTED
REPEATABLE READ
SERIALIZABLE
```
