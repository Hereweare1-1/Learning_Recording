# 数据库基础概念

## 1. 数据库、DBMS与SQL

### 1.1 数据库

**数据库（Database，DB）**是按照一定结构组织和保存的数据集合。

例如，学习项目中的`fastapi_test`就是一个数据库，其中可以存放用户表、图书表和聊天记录表等数据表。

### 1.2 数据库管理系统

**数据库管理系统（Database Management System，DBMS）**是用来创建、管理和操作数据库的软件。

它负责接收操作命令，并完成数据的查询、新增、修改、删除以及权限管理等工作。MySQL、PostgreSQL和Oracle都属于DBMS。

### 1.3 SQL

**SQL（Structured Query Language，结构化查询语言）**是操作关系型数据库的语言。

开发者通常不直接操作数据库文件，而是向DBMS发送SQL，由DBMS完成具体的数据操作。

```text
开发者 → 编写SQL → DBMS执行SQL → 操作数据库中的数据
```

SQL具有统一的核心标准，因此在不同关系型数据库中，常见的查询和增删改语句比较相似。不过，不同DBMS仍然存在部分语法和功能差异，这些差异通常称为SQL方言。

## 2. 三者的关系

| 名称 | 它是什么 | 示例 |
| --- | --- | --- |
| 数据库 | 有组织的数据集合 | `fastapi_test` |
| DBMS | 管理数据库的软件 | MySQL |
| SQL | 操作关系型数据库的语言 | `SELECT * FROM book;` |

可以简单记成：

```text
MySQL是管理工具
fastapi_test是被管理的数据库
SQL是我向MySQL下达操作命令时使用的语言
```

## 3. 关系型数据库与RDBMS

### 3.1 关系型数据库

**关系型数据库（Relational Database）**使用多张表组织数据，并通过表中的字段建立数据之间的联系。

表由行和列组成：

- 一列表示一种属性，例如员工姓名、职位和部门编号。
- 一行表示一条完整记录，例如某一名员工的信息。
- 不同表各自保存一类数据，避免把所有内容重复堆在一张表中。

### 3.2 表之间如何建立关系

例如，可以分别建立员工表和部门表：

**员工表**

| id | name | job | dept_id |
| --- | --- | --- | --- |
| 1 | 金庸 | 总裁 | 2 |
| 2 | 张无忌 | 项目经理 | 1 |
| 3 | 杨逍 | 开发 | 3 |

**部门表**

| id | name |
| --- | --- |
| 1 | 研发部 |
| 2 | 总经办 |
| 3 | 财务部 |

其中：

- 部门表的`id`用于唯一标识一个部门，通常作为主键。
- 员工表的`dept_id`保存员工所属部门的编号。
- `员工表.dept_id`对应`部门表.id`，因此可以根据部门编号找到部门名称。
- 如果在数据库中为这种关联设置约束，`dept_id`就可以作为指向部门表的外键。

主键和外键的具体定义与写法，等学习表约束时再详细整理。

### 3.3 RDBMS是什么

**RDBMS（Relational Database Management System，关系型数据库管理系统）**是管理关系型数据库的软件，例如MySQL、PostgreSQL和Oracle。

关系型数据库与RDBMS不能完全等同：

| 名称 | 含义 | 示例 |
| --- | --- | --- |
| 关系型数据库 | 使用表和表关系保存的数据 | `fastapi_test` |
| RDBMS | 管理关系型数据库的软件 | MySQL |

## 4. MySQL中的数据层级

客户端把SQL发送给MySQL，MySQL再操作指定数据库中的数据表：

```text
客户端 → MySQL（RDBMS） → 数据库 → 数据表 → 行和列
```

一个MySQL服务可以管理多个数据库，一个数据库中又可以包含多张数据表。例如：

```text
MySQL
├─ fastapi_test
│  ├─ book表
│  └─ user表
└─ 其他数据库
```

客户端可以是MySQL命令行、数据库管理工具，也可以是使用`aiomysql`连接数据库的Python程序。
