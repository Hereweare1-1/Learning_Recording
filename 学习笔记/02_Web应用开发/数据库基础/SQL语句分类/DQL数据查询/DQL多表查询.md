# DQL多表查询

多表查询用于从两张或多张相互关联的数据表中获取数据。

一对多、多对多和一对一描述的是表之间的数据关系，不是具体的查询语法。设计表结构时先确定关系，查询时再根据主键和外键等关联字段组合数据。

## 1. 多表关系概述

| 关系 | 示例 | 实现方式 |
| --- | --- | --- |
| 一对多（多对一） | 一个部门有多个员工，一个员工属于一个部门 | 在“多”的一方建立外键，引用“一”的一方的主键 |
| 多对多 | 一个学生可以选择多门课程，一门课程可以被多个学生选择 | 建立中间表，使用两个外键分别引用两张表的主键 |
| 一对一 | 一个用户对应一份用户详情 | 在其中一张表建立外键，并为外键添加唯一约束 |

## 2. 一对多（多对一）

部门和员工是一对多关系：

- 一个部门可以有多个员工。
- 一个员工只属于一个部门。
- 部门是“一”的一方，员工是“多”的一方。

实现时，在“多”的一方建立外键，引用“一”的一方的主键：

```text
employee.department_id → department.id
```

`employee.department_id`保存员工所属部门的编号，并通过外键引用`department.id`。

## 3. 多对多

学生和课程是多对多关系：

- 一个学生可以选择多门课程。
- 一门课程可以被多个学生选择。

不能只在学生表或课程表中添加一个普通外键来完整表示这种关系。需要建立第三张中间表，并使用两个外键分别引用两张表：

```text
student_course.student_id → student.id
student_course.course_id  → course.id
```

中间表中的一条记录表示“某个学生选择了某门课程”。通常还会为`student_id`和`course_id`的组合添加主键或唯一约束，防止同一个学生重复选择同一门课程。

## 4. 一对一

用户基本信息和用户详细信息是一对一关系：

- 一个用户最多对应一份用户详情。
- 一份用户详情只属于一个用户。

实现时可以在其中一张表建立外键，引用另一张表的主键，并为这个外键添加`UNIQUE`唯一约束：

```text
user_detail.user_id → user.id
```

外键保证`user_detail.user_id`引用的用户确实存在，唯一约束保证同一个用户编号在详情表中最多出现一次。

实际设计中，通常把外键放在依赖另一张表才能存在的详情表中。例如用户详情依赖用户存在，因此将`user_id`放在`user_detail`表中更容易理解。
