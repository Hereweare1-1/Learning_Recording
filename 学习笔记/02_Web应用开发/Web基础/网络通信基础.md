# 网络通信基础

这篇笔记整理IP地址、端口号、DNS、网络模型和TCP等网络通信基础。

## 1. IP地址和端口号

访问一个Web网站时，需要先找到服务器，再找到服务器上负责处理请求的程序。

可以把服务器想象成一栋大楼：

- **IP地址**相当于大楼的地址，用来找到哪一台计算机。
- **端口号（Port）**相当于房间号，用来找到计算机中的某个程序。

### 1.1 IP地址

IP地址用于标识网络中的设备。例如：

```text
110.242.69.21
127.0.0.1
```

其中，`127.0.0.1`表示本机，也就是当前正在使用的计算机。

IP地址主要有两种版本：

| 类型 | 表现形式 |
| --- | --- |
| IPv4 | 由四组十进制数字组成，例如`192.168.1.10` |
| IPv6 | 通常由多组十六进制数字组成，例如`2001:db8::1` |

#### 查看本机IP地址

Windows使用：

```bash
ipconfig
```

Linux通常使用：

```bash
ip addr
```

macOS可以使用：

```bash
ifconfig
```

#### 使用ping检查网络

`ping`用于检查当前计算机能否与目标地址进行基本的网络通信。

```bash
# 检查能否访问该域名对应的服务器
ping www.baidu.com

# 检查能否访问局域网中的某台设备
ping 192.168.1.10

# 检查本机的网络协议是否正常工作
ping 127.0.0.1
```

> [!note]
> 某些服务器或防火墙会禁止回应`ping`。因此，`ping`失败不一定代表网络完全不可用。

### 1.2 端口号

一台计算机可以同时运行多个网络程序。为了把数据交给正确的程序，提供网络服务的程序需要监听相应的端口号。

可以把端口理解为房间的门：IP地址先帮助我找到计算机，端口号再帮助我找到这台计算机中负责接收数据的程序。并不是每个正在运行的程序都一定会使用网络端口。

端口号是一个整数，取值范围是`0～65535`。按照用途，可以大致分为：

| 范围 | 分类 | 简单说明 |
| ---: | --- | --- |
| `0～1023` | 系统端口（知名端口） | 常用于HTTP、HTTPS等通用服务 |
| `1024～49151` | 用户端口（注册端口） | 常由应用程序或特定服务使用 |
| `49152～65535` | 动态端口（私有端口） | 常由客户端临时使用 |

我现在不需要背诵完整范围，先记住常用服务有固定的默认端口，而客户端通信时也可能临时获得一个端口。

常见端口如下：

| 服务 | 默认端口 | 说明 |
| --- | ---: | --- |
| HTTP | `80` | 访问普通的Web网站 |
| HTTPS | `443` | 加密访问Web网站 |
| FastAPI开发服务 | `8000` | 常见的开发环境端口，不是固定要求 |

> [!tip] 简单记忆
> IP地址负责找到计算机，端口号负责找到计算机中的程序。

### 1.3 IP地址和端口号组合使用

IP地址和端口号通常写成下面的形式：

```text
IP地址:端口号
```

在网络通信中，可以把“IP地址 + 端口号”理解为一个具体的通信地址，也叫**套接字地址（Socket Address）**。

例如：

```text
127.0.0.1:8000
```

它表示：访问本机中监听`8000`端口的程序。

在[[FastAPI快速入门|FastAPI]]中，可以这样启动服务：

```python
import uvicorn

uvicorn.run("main:app", host="127.0.0.1", port=8000)
```

浏览器可以通过下面的地址访问该服务：

```text
http://127.0.0.1:8000
```

## 2. DNS是什么

人更容易记住`www.example.com`这样的域名，但计算机通信时需要使用IP地址。

**DNS（域名系统）**的作用就是把域名转换成对应的IP地址，可以把它理解为网络中的“电话簿”。

```text
域名 www.example.com
        ↓ DNS解析
IP地址 93.184.216.34
```

一个域名可能对应多个IP地址，这样可以让多台服务器共同处理请求。

## 3. 网络模型

网络模型把复杂的网络通信拆分成不同层，每一层只负责一部分工作。可以把它理解为：数据要经过多个分工不同的“部门”，才能从一个程序传到另一个程序。

### 3.1 OSI七层模型

OSI模型主要用于帮助理解网络通信，一共分为七层：

```text
应用层
表示层
会话层
传输层
网络层
数据链路层
物理层
```

OSI模型通过分层划分网络通信中的不同职责，便于理解协议之间的关系和定位网络问题。

### 3.2 TCP/IP四层模型

实际学习和开发中更常见的是TCP/IP四层模型，可以把它看作OSI模型的简化版本。

| TCP/IP层级 | 主要作用 | 常见内容 |
| --- | --- | --- |
| 应用层 | 规定应用程序如何组织和交换数据 | HTTP、HTTPS、DNS、FTP、SMTP |
| 传输层 | 把数据送到目标设备中的具体程序 | TCP、UDP、端口号 |
| 网络层 | 根据IP地址把数据送到目标设备 | IP、路由 |
| 网络接口层 | 负责数据在网线、Wi-Fi等实际网络中的传输 | 以太网、Wi-Fi |

发送HTTP请求时，可以简单理解为：

```text
HTTP请求
   ↓ 应用层组织请求内容
TCP传输
   ↓ 传输层根据端口找到程序
IP传输
   ↓ 网络层根据IP地址找到设备
网线或Wi-Fi
   ↓ 网络接口层实际传输数据
目标服务器
```

### 3.3 TCP的特点

**TCP（Transmission Control Protocol，传输控制协议）**是传输层协议，常用于需要稳定、完整传输数据的场景。

- **面向连接**：通信双方要先建立连接，之后才能传输数据；通信结束后需要关闭连接并释放资源。
- **可靠传输**：TCP会尽量保证数据完整、按顺序到达。网页访问、接口请求和文件传输等场景经常会使用TCP。
- **双向通信**：连接建立后，客户端和服务器都可以发送和接收数据。对一方来说，发出的数据是输出流，收到的数据是输入流。
- **存在额外开销**：建立连接和保证可靠性都需要额外处理，因此TCP通常比UDP复杂，但不能简单理解成“TCP速度一定很慢”。

```text
客户端  ──── 输出数据 ────>  服务器
客户端  <──── 输入数据 ────  服务器
```

> [!tip] TCP通信流程
> TCP先建立连接，再可靠地双向传输数据，最后关闭连接。

### 3.4 Web开发中的常用网络知识

Web应用的一次请求会同时涉及应用层、传输层和网络层中的多个概念：

- **HTTP/HTTPS**：规定请求方法、URL、请求头、请求体、状态码和响应数据等应用层通信格式。
- **TCP**：为HTTP等协议提供面向连接、可靠且双向的数据传输。
- **端口号**：用于找到设备中负责通信的具体程序，例如FastAPI常用`8000`端口。
- **IP和DNS**：IP用于找到设备，DNS用于把域名解析为IP地址。
- **UDP**：提供无连接的数据报传输，不保证数据一定到达。
- **网络接口层**：负责通过网线、Wi-Fi等实际网络传输数据。
