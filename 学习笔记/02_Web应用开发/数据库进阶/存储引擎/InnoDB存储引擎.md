# InnoDB存储引擎

InnoDB是兼顾可靠性和性能的通用存储引擎，也是MySQL 8.4的默认存储引擎。普通业务系统如果没有特殊需求，通常优先使用InnoDB。

## 1. 核心特点

### 1.1 支持事务

InnoDB的DML操作遵循ACID模型，支持事务提交、事务回滚和崩溃恢复，适合需要保证数据可靠性的业务。

### 1.2 支持行级锁

InnoDB主要使用行级锁。不同事务操作不同行时可以并发执行，相比只支持表级锁的引擎，通常具有更好的并发能力。

行级锁并不表示任何操作都只锁一行。实际锁定范围会受到索引、查询条件和事务隔离级别等因素影响。

### 1.3 支持外键

InnoDB支持`FOREIGN KEY`外键约束，可以维护父表与子表之间的引用完整性。

### 1.4 使用聚簇索引组织数据

InnoDB会使用聚簇索引组织表数据。通常情况下，表的主键就是聚簇索引，按照主键查询数据具有较高效率。

## 2. InnoDB表空间文件

### 2.1 独立表空间

启用`innodb_file_per_table`时，每张新建的InnoDB表默认拥有一个独立的表空间文件：

```text
表名.ibd
```

`.ibd`文件主要保存该表的数据和索引。MySQL 8.x还会在InnoDB表空间文件中保存序列化字典信息（SDI），作为表和表空间元数据的冗余信息。

查看是否启用独立表空间：

```sql
SHOW VARIABLES LIKE 'innodb_file_per_table';
```

| 查询结果 | 含义 |
| --- | --- |
| `ON` | 新建表默认使用独立表空间 |
| `OFF` | 新建表默认存放在系统表空间 |

> [!note] `.ibd`并非绝对一表一文件
> InnoDB表也可以放入系统表空间或通用表空间。因此，“一张表对应一个`.ibd`文件”只适用于独立表空间模式。

### 2.2 MySQL版本差异

- MySQL 5.7及更早版本通常使用`.frm`文件保存表结构信息。
- MySQL 8.0起使用事务型数据字典，不再使用`.frm`文件。
- InnoDB的SDI信息存放在表空间文件内部，而不是为每张InnoDB表单独创建`.sdi`文件。

## 3. InnoDB逻辑存储结构

InnoDB的逻辑存储结构从大到小可以理解为：

```text
表空间（Tablespace）
  ↓
段（Segment）
  ↓
区（Extent）
  ↓
页（Page）
  ↓
行（Row）
```

### 3.1 表空间（Tablespace）

表空间是InnoDB存储结构中的最高层容器，由多个段组成。独立表空间、系统表空间和通用表空间都属于表空间。

### 3.2 段（Segment）

段由多个区组成，用于管理特定类型的数据。一个InnoDB索引通常包含叶子节点段和非叶子节点段。

### 3.3 区（Extent）

区由一组连续的页组成。在默认`16KB`页大小下，一个区通常为`1MB`，包含64个连续页。

### 3.4 页（Page）

页是InnoDB管理磁盘数据的基本单位，默认大小为`16KB`。一个页中可以存放多行记录，也可以保存索引节点或其他管理信息。

### 3.5 行（Row）

行是表中的一条记录。除用户定义的字段外，InnoDB还会维护事务ID、回滚指针等隐藏信息，用于实现事务和多版本并发控制。

常见隐藏信息包括：

- `DB_TRX_ID`：记录最后一次插入或更新该行的事务ID。
- `DB_ROLL_PTR`：指向对应的撤销日志记录。
- `DB_ROW_ID`：当表中没有可用的聚簇索引键时，InnoDB生成的隐藏行ID。

当前阶段重点记住整体包含关系即可：表空间包含段，段包含区，区包含页，页中存放行。
