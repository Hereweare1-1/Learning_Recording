# MySQL体系结构

MySQL采用可插拔的存储引擎架构。MySQL Server负责连接管理和SQL处理，存储引擎负责实际的数据读写。上层程序使用统一的SQL接口，不需要直接处理不同存储引擎的底层细节。

## 1. 整体结构

为了方便理解，可以把MySQL体系结构从上到下分为四层：

```text
客户端
  ↓
连接层
  ↓
服务层
  ↓
引擎层
  ↓
存储层
```

| 层次 | 主要作用 |
| --- | --- |
| 连接层 | 接收客户端连接，完成身份认证、权限检查和连接管理 |
| 服务层 | 完成SQL解析、查询优化和语句执行等通用工作 |
| 引擎层 | 通过存储引擎读写数据和索引，例如InnoDB、MyISAM和MEMORY |
| 存储层 | 把数据、索引和日志保存到磁盘等存储介质中 |

## 2. 连接层

连接层负责客户端与MySQL Server之间的通信。

常见客户端可以通过JDBC、ODBC、Python数据库驱动等连接器访问MySQL。建立连接时，MySQL会完成身份认证、权限检查和连接管理，然后把请求交给服务层处理。

## 3. 服务层

服务层包含大多数与存储引擎无关的核心功能，主要包括：

- SQL接口：接收客户端发送的SQL语句。
- 解析器：检查SQL语法，并识别语句中的表、字段和操作。
- 查询优化器：选择合适的索引、表连接顺序和执行方案。
- 执行器：按照执行计划调用存储引擎接口，并返回执行结果。

> [!note] 关于图中的“缓存”
> 一些旧版体系结构图会单独画出查询缓存。MySQL 8.0已经移除查询缓存，但服务器和存储引擎内部仍然存在其他用途的缓存与缓冲区，不能把两者混为一谈。

## 4. 引擎层

引擎层负责通过存储引擎完成数据和索引的实际读写。MySQL支持可插拔存储引擎，同一套服务层可以调用不同的存储引擎。

不同存储引擎的功能和适用场景不同。例如，是否支持事务、外键、行级锁以及崩溃恢复，都与具体存储引擎有关。

MySQL 8.4默认使用InnoDB。当前学习和实际项目中，应优先掌握InnoDB。

## 5. 存储层

存储层负责把数据真正保存到文件系统或其他存储介质中，涉及数据文件、索引文件、日志文件等内容。

具体使用哪些文件、文件如何组织，取决于存储引擎和MySQL配置，不同存储引擎的实现可能不同。

## 6. 一条查询语句的大致执行过程

```text
客户端发送SQL
  ↓
连接层验证身份和权限
  ↓
服务层解析并优化SQL
  ↓
执行器调用存储引擎接口
  ↓
存储引擎读取数据和索引
  ↓
MySQL向客户端返回结果
```

需要重点理解：服务层负责“理解并执行SQL”，存储引擎负责“按照要求读写数据”。
