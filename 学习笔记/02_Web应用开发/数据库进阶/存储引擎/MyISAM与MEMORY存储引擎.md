# MyISAM与MEMORY存储引擎

MyISAM和MEMORY都是MySQL提供的存储引擎，但它们不支持事务，适用范围也比InnoDB更窄。当前学习中应重点掌握它们与InnoDB的区别，而不是把它们作为普通业务表的默认选择。

## 1. MyISAM存储引擎

### 1.1 简介

MyISAM是MySQL早期常用的存储引擎。它不支持事务和外键，使用表级锁，更适合只读、读多写少或低并发的场景。

MySQL 8.4的默认存储引擎是InnoDB，不再是MyISAM。

### 1.2 主要特点

- 不支持事务，不能使用`ROLLBACK`撤销已经完成的修改。
- 不支持外键约束。
- 使用表级锁，同一时刻对表进行写操作的会话会受到较大限制。
- 支持B-tree索引和全文索引，不支持用户创建Hash索引。
- 磁盘占用相对紧凑，适合只读或读多写少的数据。

“MyISAM访问速度快”需要结合场景理解：它在部分只读、低并发或全表扫描场景中可能表现较好，但表级锁会限制高并发读写能力，不能简单认为它一定比InnoDB快。

### 1.3 MyISAM文件

MyISAM表主要使用以下文件：

| 文件 | 作用 |
| --- | --- |
| `表名.MYD` | 保存表数据，`MYD`表示MyData |
| `表名.MYI` | 保存索引，`MYI`表示MyIndex |
| `表名.sdi` | MySQL 8.x中可用于保存序列化字典信息，不保存业务数据 |

MySQL 8.x中的表定义以服务器的数据字典为准，不能把`.sdi`简单理解成旧版`.frm`文件的完全等价替代品。

创建MyISAM表：

```sql
CREATE TABLE article_archive (
    id BIGINT PRIMARY KEY,
    title VARCHAR(100) NOT NULL
) ENGINE = MyISAM;
```

## 2. MEMORY存储引擎

### 2.1 简介

MEMORY存储引擎把表数据保存在内存中，可以用于体量较小、允许丢失的临时数据或只读缓存。

MySQL服务器停止或重启后，MEMORY表的结构仍然存在，但表中的数据会丢失。因此，不能用它保存重要业务数据。

### 2.2 主要特点

- 数据保存在内存中，不具有数据持久性。
- 不支持事务和外键。
- 使用表级锁，并发写入能力有限。
- 同时支持Hash索引和B-tree索引，默认使用Hash索引。
- 不支持`BLOB`和`TEXT`字段。
- 数据量受到可用内存及相关配置的限制。

MEMORY表虽然使用内存，但不代表任何场景都比InnoDB快。在高并发读写场景中，表级锁可能成为性能瓶颈。

### 2.3 MEMORY表的文件

MEMORY引擎不会为表数据和索引创建磁盘文件，表定义保存在MySQL数据字典中。因此，不能把截图中的“`.sdi`保存MEMORY表结构”当作MySQL 8.4的通用文件规则。

创建使用默认Hash索引的MEMORY表：

```sql
CREATE TABLE city_cache (
    id INT PRIMARY KEY,
    city_name VARCHAR(50) NOT NULL
) ENGINE = MEMORY;
```

显式创建B-tree索引：

```sql
CREATE INDEX idx_city_name
ON city_cache (city_name) USING BTREE;
```

## 3. InnoDB、MyISAM与MEMORY对比

| 对比项 | InnoDB | MyISAM | MEMORY |
| --- | --- | --- | --- |
| 数据位置 | 主要保存在磁盘，常用数据通过缓冲池缓存 | 保存在磁盘 | 保存在内存 |
| 数据持久性 | 支持 | 支持，但崩溃恢复能力弱于InnoDB | 不支持，重启后数据丢失 |
| 事务 | 支持 | 不支持 | 不支持 |
| 锁粒度 | 主要使用行级锁 | 表级锁 | 表级锁 |
| 外键 | 支持 | 不支持 | 不支持 |
| B-tree索引 | 支持 | 支持 | 支持 |
| Hash索引 | 不能直接创建，内部可使用自适应Hash索引 | 不支持 | 支持，默认使用 |
| 全文索引 | 支持 | 支持 | 不支持 |
| 典型场景 | 普通业务表和高并发读写 | 只读、读多写少或遗留系统 | 可丢失的临时数据和小型缓存 |

## 4. 如何理解性能差异

不能脱离场景直接给三种引擎排出固定的速度顺序：

- InnoDB适合需要事务、可靠性和高并发读写的业务。
- MyISAM可能适合低并发、读多写少的数据，但表级锁会限制并发写入。
- MEMORY省去了磁盘数据访问，但表级锁、内存容量和数据易失性限制了它的用途。
- 批量插入速度还会受到索引数量、事务提交方式、磁盘性能和SQL写法等因素影响。

当前阶段的选择原则是：普通业务表优先使用InnoDB，只有在明确了解限制并且场景匹配时，才考虑MyISAM或MEMORY。
