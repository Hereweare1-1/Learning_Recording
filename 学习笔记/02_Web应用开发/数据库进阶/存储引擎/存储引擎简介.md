# 存储引擎简介

存储引擎是MySQL中负责数据存储、索引维护以及数据读取和修改的组件。MySQL Server负责理解和执行SQL，具体的数据读写工作则交给存储引擎完成。

## 1. 存储引擎的作用

不同存储引擎可以采用不同的数据组织和读写方式，并提供不同的功能。

存储引擎通常会影响以下方面：

- 数据和索引如何存储。
- 是否支持事务及事务回滚。
- 使用表级锁还是行级锁。
- 是否支持外键约束。
- 是否具有崩溃恢复能力。
- 适合读多写少还是高并发读写等场景。

## 2. 存储引擎基于表

MySQL的存储引擎是在创建表时指定的，而不是为整个数据库统一指定的。因此，同一个数据库中的不同表可以使用不同的存储引擎。

由于存储引擎决定表的存储和访问方式，所以有时也称为“表类型”。

```text
数据库
├─ 用户表：InnoDB
├─ 临时统计表：MEMORY
└─ 历史归档表：ARCHIVE
```

实际项目中不应为了使用不同引擎而刻意混用。MySQL 8.4默认使用InnoDB，大多数普通业务表优先使用InnoDB即可。

## 3. 创建表时指定存储引擎

在`CREATE TABLE`语句末尾使用`ENGINE`选项指定存储引擎：

```sql
CREATE TABLE employee (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '员工编号',
    name VARCHAR(50) NOT NULL COMMENT '员工姓名'
) ENGINE = InnoDB COMMENT '员工表';
```

通用语法如下：

```sql
CREATE TABLE 表名 (
    字段名 数据类型 [字段约束] [COMMENT '字段注释'],
    ...
) ENGINE = 存储引擎名称 [COMMENT '表注释'];
```

如果省略`ENGINE`选项，MySQL会使用当前默认的存储引擎。

## 4. 查看支持的存储引擎

查看当前MySQL服务器支持的存储引擎：

```sql
SHOW ENGINES;
```

查询结果中的`Support`列用于说明引擎是否可用：

| `Support`值 | 含义 |
| --- | --- |
| `DEFAULT` | 支持，并且是当前默认存储引擎 |
| `YES` | 支持使用 |
| `NO` | 当前版本不支持 |
| `DISABLED` | 已编译，但被禁用 |

结果中的`Transactions`、`XA`和`Savepoints`列分别表示该引擎是否支持事务、XA事务和保存点。

查看当前默认的存储引擎：

```sql
SELECT @@default_storage_engine;
```

> [!warning] 注意命令区别
> `SHOW ENGINES`用于列出存储引擎；`SHOW ENGINE InnoDB STATUS`用于查看InnoDB的运行状态，两者不是同一条命令。
