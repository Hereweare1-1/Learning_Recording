# Web网络基础

## 1. Web网站的组成部分

- 前端程序：负责界面展示。
- 后端程序：负责业务逻辑处理。
- 数据库：负责数据的存储与管理。

## 2. 前端网页程序的组成部分

- HTML：负责网页的结构和内容。
- CSS：负责网页的样式。
- JavaScript（JS）：负责网页的动作行为和交互效果。

## 3. 客户端和服务器

- **客户端**：主动发起请求的一方，例如浏览器、Python程序和Vue前端。
- **服务器**：接收请求、处理请求并提供服务的一方。

基本过程：

```text
客户端 → 发送请求 → 服务器
客户端 ← 返回响应 ← 服务器
```

## 4. IP地址和端口号

访问一个Web网站时，需要先找到服务器，再找到服务器上负责处理请求的程序。

可以把服务器想象成一栋大楼：

- **IP地址**相当于大楼的地址，用来找到哪一台计算机。
- **端口号（Port）**相当于房间号，用来找到计算机中的某个程序。

### 4.1 IP地址

IP地址用于标识网络中的设备。例如：

```text
110.242.69.21
127.0.0.1
```

其中，`127.0.0.1`表示本机，也就是当前正在使用的计算机。

### 4.2 端口号

一台计算机可以同时运行多个网络程序。为了区分这些程序，需要给它们分配不同的端口号。

端口号是一个整数，取值范围是`0～65535`。常见端口如下：

| 服务 | 默认端口 | 说明 |
| --- | ---: | --- |
| HTTP | `80` | 访问普通的Web网站 |
| HTTPS | `443` | 加密访问Web网站 |
| FastAPI开发服务 | `8000` | 常见的开发环境端口，不是固定要求 |

> [!tip] 简单记忆
> IP地址负责找到计算机，端口号负责找到计算机中的程序。

### 4.3 IP地址和端口号组合使用

IP地址和端口号通常写成下面的形式：

```text
IP地址:端口号
```

在网络通信中，可以把“IP地址 + 端口号”理解为一个具体的通信地址，也叫**套接字地址（Socket Address）**。

例如：

```text
127.0.0.1:8000
```

它表示：访问本机中监听`8000`端口的程序。

在[[FastAPI基础|FastAPI]]中，可以这样启动服务：

```python
import uvicorn

uvicorn.run("main:app", host="127.0.0.1", port=8000)
```

浏览器可以通过下面的地址访问该服务：

```text
http://127.0.0.1:8000
```

## 5. DNS是什么

人更容易记住`www.example.com`这样的域名，但计算机通信时需要使用IP地址。

**DNS（域名系统）**的作用就是把域名转换成对应的IP地址，可以把它理解为网络中的“电话簿”。

```text
域名 www.example.com
        ↓ DNS解析
IP地址 93.184.216.34
```

一个域名可能对应多个IP地址，这样可以让多台服务器共同处理请求。

## 6. URL是什么

**URL**就是网络资源的地址，用来告诉客户端“使用什么协议，请求哪台服务器上的哪个资源”。

例如：

```text
https://api.example.com/chat
```

可以简单拆分为：

```text
https://          → 使用HTTPS协议
api.example.com   → 服务器域名
/chat             → 资源或接口路径
```

如果使用非默认端口，URL中还会出现端口号：

```text
http://127.0.0.1:8000/users
```

## 7. HTTP请求与响应

**HTTP**是客户端和服务器之间进行通信的一套规则，也叫协议。

```text
客户端 → HTTP请求 → 服务器
客户端 ← HTTP响应 ← 服务器
```

### 7.1 HTTP请求

一个HTTP请求通常包含：

- **URL**：请求哪个地址。
- **请求方法**：要进行什么操作，例如`GET`、`POST`、`PUT`、`DELETE`。
- **Headers（请求头）**：携带身份认证、数据类型等额外信息。
- **Body（请求体）**：发送给服务器的数据，API中经常使用JSON格式。

请求方法的具体用法可以查看[[RESTful API设计]]。

### 7.2 HTTP响应

服务器处理请求后会返回HTTP响应，响应通常包含状态码和响应数据。

常见状态码：

| 状态码 | 含义 |
| ---: | --- |
| `200` | 请求成功 |
| `400` | 请求参数有问题 |
| `401` | 没有通过身份认证 |
| `403` | 没有访问权限 |
| `404` | 请求的资源不存在 |
| `500` | 服务器内部错误 |

## 8. 访问网站的基本过程

以访问`https://www.example.com`为例：

1. 浏览器从网址中获得域名`www.example.com`。
2. 浏览器通过DNS查询域名对应的IP地址。
3. 浏览器根据IP地址找到目标服务器。
4. 因为使用的是HTTPS，所以默认连接服务器的`443`端口。
5. 服务器中的Web程序处理请求，并把网页内容返回给浏览器。

```text
输入域名
   ↓
DNS将域名解析为IP地址
   ↓
通过IP地址找到服务器
   ↓
通过端口号找到Web程序
   ↓
Web程序返回响应
```

如果使用协议的默认端口，网址中通常不用写端口号：

```text
http://www.example.com       # 默认使用80端口
https://www.example.com      # 默认使用443端口
```

如果程序使用的不是默认端口，就需要在网址中写出来：

```text
http://127.0.0.1:8000
```

## 9. API是什么

**API（应用程序接口）**是程序之间进行交互的入口和规则。

例如，Python程序可以通过HTTP请求调用大模型API：

```text
Python程序
   ↓ 调用API
大模型服务器
   ↓ 返回响应
Python程序得到结果
```

可以把API简单理解为：**一个程序向另一个程序请求功能的入口**。

大模型调用的具体过程可以查看[[大模型API调用]]。
