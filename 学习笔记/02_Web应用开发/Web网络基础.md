# Web网络基础

## 1. Web网站的组成部分

- 前端程序：负责界面展示。
- 后端程序：负责业务逻辑处理。
- 数据库：负责数据的存储与管理。

## 2. 前端网页程序的组成部分

- HTML：负责网页的结构和内容。
- CSS：负责网页的样式。
- JavaScript（JS）：负责网页的动作行为和交互效果。

## 3. 客户端和服务器

- **客户端**：主动发起请求的一方，例如浏览器、Python程序和Vue前端。
- **服务器**：接收请求、处理请求并提供服务的一方。

基本过程：

```text
客户端 → 发送请求 → 服务器
客户端 ← 返回响应 ← 服务器
```

## 4. IP地址和端口号

访问一个Web网站时，需要先找到服务器，再找到服务器上负责处理请求的程序。

可以把服务器想象成一栋大楼：

- **IP地址**相当于大楼的地址，用来找到哪一台计算机。
- **端口号（Port）**相当于房间号，用来找到计算机中的某个程序。

### 4.1 IP地址

IP地址用于标识网络中的设备。例如：

```text
110.242.69.21
127.0.0.1
```

其中，`127.0.0.1`表示本机，也就是当前正在使用的计算机。

### 4.2 端口号

一台计算机可以同时运行多个网络程序。为了区分这些程序，需要给它们分配不同的端口号。

端口号是一个整数，取值范围是`0～65535`。常见端口如下：

| 服务 | 默认端口 | 说明 |
| --- | ---: | --- |
| HTTP | `80` | 访问普通的Web网站 |
| HTTPS | `443` | 加密访问Web网站 |
| FastAPI开发服务 | `8000` | 常见的开发环境端口，不是固定要求 |

> [!tip] 简单记忆
> IP地址负责找到计算机，端口号负责找到计算机中的程序。

### 4.3 IP地址和端口号组合使用

IP地址和端口号通常写成下面的形式：

```text
IP地址:端口号
```

在网络通信中，可以把“IP地址 + 端口号”理解为一个具体的通信地址，也叫**套接字地址（Socket Address）**。

例如：

```text
127.0.0.1:8000
```

它表示：访问本机中监听`8000`端口的程序。

在[[FastAPI快速入门|FastAPI]]中，可以这样启动服务：

```python
import uvicorn

uvicorn.run("main:app", host="127.0.0.1", port=8000)
```

浏览器可以通过下面的地址访问该服务：

```text
http://127.0.0.1:8000
```

## 5. DNS是什么

人更容易记住`www.example.com`这样的域名，但计算机通信时需要使用IP地址。

**DNS（域名系统）**的作用就是把域名转换成对应的IP地址，可以把它理解为网络中的“电话簿”。

```text
域名 www.example.com
        ↓ DNS解析
IP地址 93.184.216.34
```

一个域名可能对应多个IP地址，这样可以让多台服务器共同处理请求。

## 6. URL是什么

**URL**就是网络资源的地址，用来告诉客户端“使用什么协议，请求哪台服务器上的哪个资源”。

例如：

```text
https://api.example.com/chat
```

可以简单拆分为：

```text
https://          → 使用HTTPS协议
api.example.com   → 服务器域名
/chat             → 资源或接口路径
```

如果使用非默认端口，URL中还会出现端口号：

```text
http://127.0.0.1:8000/users
```

## 7. 网络模型

网络模型把复杂的网络通信拆分成不同层，每一层只负责一部分工作。可以把它理解为：数据要经过多个分工不同的“部门”，才能从一个程序传到另一个程序。

### 7.1 OSI七层模型

OSI模型主要用于帮助理解网络通信，一共分为七层：

```text
应用层
表示层
会话层
传输层
网络层
数据链路层
物理层
```

现阶段只需要知道这些层存在，以及网络通信采用了分层设计，**不需要死记每一层的所有协议和细节**。

### 7.2 TCP/IP四层模型

实际学习和开发中更常见的是TCP/IP四层模型，可以把它看作OSI模型的简化版本。

| TCP/IP层级 | 主要作用 | 常见内容 |
| --- | --- | --- |
| 应用层 | 规定应用程序如何组织和交换数据 | HTTP、HTTPS、DNS、FTP、SMTP |
| 传输层 | 把数据送到目标设备中的具体程序 | TCP、UDP、端口号 |
| 网络层 | 根据IP地址把数据送到目标设备 | IP、路由 |
| 网络接口层 | 负责数据在网线、Wi-Fi等实际网络中的传输 | 以太网、Wi-Fi |

发送HTTP请求时，可以简单理解为：

```text
HTTP请求
   ↓ 应用层组织请求内容
TCP传输
   ↓ 传输层根据端口找到程序
IP传输
   ↓ 网络层根据IP地址找到设备
网线或Wi-Fi
   ↓ 网络接口层实际传输数据
目标服务器
```

### 7.3 现阶段应该学到什么程度

我的求职方向是智能应用开发，因此现阶段应当**重点关注应用层中的HTTP和HTTPS，不需要深入研究底层网络实现**。

但不能只知道HTTP，至少还要理解：

- **HTTP/HTTPS**：重点掌握请求方法、URL、请求头、请求体、状态码和响应数据。
- **TCP**：知道HTTP通信通常需要依靠TCP传输，以及TCP负责可靠传输即可。
- **端口号**：知道端口用于找到设备中的具体程序，例如FastAPI常用`8000`端口。
- **IP和DNS**：知道IP用于找到设备，DNS用于把域名解析为IP地址。
- **UDP和网络接口层**：现阶段知道它们的作用即可，不需要学习内部实现。

> [!tip] 学习重点
> OSI七层认识名称即可；TCP/IP四层理解各层职责；HTTP/HTTPS需要重点掌握；TCP、IP、端口和DNS需要能解释它们如何配合完成一次请求。

## 8. HTTP请求与响应

**HTTP**全称为HyperText Transfer Protocol，中文是“超文本传输协议”。它是客户端和服务器之间进行通信的一套规则。

```text
客户端 → HTTP请求 → 服务器
客户端 ← HTTP响应 ← 服务器
```

### 8.1 HTTP的基本特点

#### 请求—响应模型

通常由客户端先发送一次请求，服务器处理后返回一次响应。

```text
客户端发送请求 → 服务器处理请求 → 服务器返回响应
```

#### 无状态

HTTP本身不会自动记住前后两次请求来自同一个用户，每次请求在协议层面都是相对独立的。

实际网站可以使用Cookie、Session或Token保存登录状态，所以“HTTP无状态”不等于“网站不能记住用户”。

#### 数据格式与传输方式

- HTTP规定了请求和响应的结构，但请求体和响应体不一定只能传递文本，也可以传递图片、视频、JSON等数据。
- HTTP/1.1中的请求行和请求头是文本形式，因此学习时可以直接阅读。
- HTTP/1.1和HTTP/2通常通过TCP传输；HTTP/3使用基于UDP的QUIC协议。

> [!note] 注意版本差异
> 我可以先把HTTP理解为“基于请求—响应模型的应用层协议”，但也要知道：“HTTP全部基于文本、底层一定使用TCP”只适合初步理解HTTP/1.1，并不适用于所有HTTP版本。

### 8.2 HTTP请求

一个HTTP请求通常包含：

- **URL**：请求哪个地址。
- **请求方法**：要进行什么操作，例如`GET`、`POST`、`PUT`、`DELETE`。
- **Headers（请求头）**：携带身份认证、数据类型等额外信息。
- **Body（请求体）**：发送给服务器的数据，API中经常使用JSON格式。

#### HTTP请求报文的结构

下面是一段简化后的HTTP请求：

```http
POST /api/courses HTTP/1.1
Host: localhost:90
Accept: application/json
Content-Type: application/json
Authorization: Bearer example-token

{"name": "Python", "status": 1}
```

它由三部分组成：

```text
请求行
请求头
空行
请求体（可以没有）
```

**请求行**

请求行位于第一行，由请求方法、资源路径和HTTP版本组成：

```text
POST /api/courses HTTP/1.1
```

| 内容 | 示例 | 作用 |
| --- | --- | --- |
| 请求方法 | `POST` | 表示要进行什么操作 |
| 资源路径 | `/api/courses` | 表示请求哪个资源 |
| HTTP版本 | `HTTP/1.1` | 表示使用的HTTP版本 |

**请求头**

请求头采用`名称: 值`的格式，每一行表示一项附加信息。

| 常见请求头 | 作用 |
| --- | --- |
| `Host` | 目标服务器的域名或地址 |
| `Accept` | 客户端希望接收的数据类型 |
| `Content-Type` | 请求体的数据类型，例如`application/json` |
| `Authorization` | 身份认证信息，例如Token |
| `Content-Length` | 请求体的字节长度 |

**请求体**

请求体用于携带提交给服务器的数据，并不是每个请求都有请求体。发送JSON数据时，需要把`Content-Type`设置为`application/json`。

```json
{
  "name": "Python",
  "status": 1
}
```

#### GET和POST如何携带参数

`GET`请求通常把参数写在URL的查询字符串中：

```http
GET /api/courses?name=Python&status=1 HTTP/1.1
```

- `?`表示查询参数开始。
- 多个参数使用`&`连接。
- 因为参数会显示在URL中，所以不适合直接放密码等敏感信息。
- `GET`请求通常不使用请求体。

`POST`请求通常把要提交的数据放在请求体中：

```json
{
  "name": "Python",
  "status": 1
}
```

| 对比项 | GET | POST |
| --- | --- | --- |
| 常见用途 | 查询、获取数据 | 提交、新增数据或执行操作 |
| 参数常见位置 | URL查询字符串 | 请求体 |
| 是否通常有请求体 | 否 | 可以有 |
| 大小限制 | URL长度会受到浏览器、服务器等限制 | 协议没有统一的固定上限，但服务器和框架通常会限制请求体大小 |

> [!important] 注意
> 不能简单地记成“POST请求大小没有限制”。实际项目中的Web服务器、网关和后端框架通常都会设置大小上限。

请求方法的具体用法可以查看[[RESTful API设计]]。

### 8.3 HTTP响应

服务器处理请求后会返回HTTP响应，响应通常包含状态码和响应数据。

#### HTTP响应报文的结构

下面是一段简化后的HTTP响应：

```http
HTTP/1.1 200 OK
Server: nginx
Content-Type: application/json
Connection: keep-alive

{"code": 1, "message": "success", "data": null}
```

它由三部分组成：

```text
响应行
响应头
空行
响应体（可以没有）
```

**响应行**

响应行位于第一行，由HTTP版本、状态码和状态说明组成：

```text
HTTP/1.1 200 OK
```

| 内容 | 示例 | 作用 |
| --- | --- | --- |
| HTTP版本 | `HTTP/1.1` | 表示使用的HTTP版本 |
| 状态码 | `200` | 使用数字说明处理结果 |
| 状态说明 | `OK` | 对状态码的简短文字说明 |

**响应头**

响应头和请求头一样，也采用`名称: 值`的格式。

| 常见响应头 | 作用 |
| --- | --- |
| `Server` | 服务器软件信息 |
| `Date` | 服务器产生响应的时间 |
| `Content-Type` | 响应体的数据类型，例如`application/json` |
| `Content-Length` | 响应体的字节长度 |
| `Connection` | 当前连接的管理方式 |

**响应体**

响应体存放服务器返回的实际数据，可以是JSON、HTML、图片或其他内容。API通常返回JSON数据：

```json
{
  "code": 1,
  "message": "success",
  "data": null
}
```

常见状态码：

| 状态码 | 含义 |
| ---: | --- |
| `200` | 请求成功 |
| `400` | 请求参数有问题 |
| `401` | 没有通过身份认证 |
| `403` | 没有访问权限 |
| `404` | 请求的资源不存在 |
| `500` | 服务器内部错误 |

## 9. 访问网站的基本过程

以访问`https://www.example.com`为例：

1. 浏览器从网址中获得域名`www.example.com`。
2. 浏览器通过DNS查询域名对应的IP地址。
3. 浏览器根据IP地址找到目标服务器。
4. 因为使用的是HTTPS，所以默认连接服务器的`443`端口。
5. 服务器中的Web程序处理请求，并把网页内容返回给浏览器。

```text
输入域名
   ↓
DNS将域名解析为IP地址
   ↓
通过IP地址找到服务器
   ↓
通过端口号找到Web程序
   ↓
Web程序返回响应
```

如果使用协议的默认端口，网址中通常不用写端口号：

```text
http://www.example.com       # 默认使用80端口
https://www.example.com      # 默认使用443端口
```

如果程序使用的不是默认端口，就需要在网址中写出来：

```text
http://127.0.0.1:8000
```

## 10. API是什么

**API（应用程序接口）**是程序之间进行交互的入口和规则。

例如，Python程序可以通过HTTP请求调用大模型API：

```text
Python程序
   ↓ 调用API
大模型服务器
   ↓ 返回响应
Python程序得到结果
```

可以把API简单理解为：**一个程序向另一个程序请求功能的入口**。

大模型调用的具体过程可以查看[[大模型API调用]]。
