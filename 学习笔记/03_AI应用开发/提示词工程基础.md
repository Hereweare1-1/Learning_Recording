# 提示词工程基础

## 1. 什么是提示词

**提示词（Prompt）**是我提供给大模型的输入，用来告诉模型要完成什么任务。

提示词不只是一个问题，也可以包含背景信息、具体要求、限制条件、参考示例和输出格式。

例如：

```text
请用初学者能理解的语言解释Python列表，并提供一个简单的代码示例。
```

## 2. 什么是提示词工程

**提示词工程（Prompt Engineering）**是设计、测试和改进提示词的过程，目标是让大模型的输出更符合我的实际需求。

```text
编写提示词
   ↓
查看模型输出
   ↓
发现不符合预期的地方
   ↓
修改提示词
   ↓
再次测试
```

提示词工程通常需要反复调整，不是写一次提示词就一定能得到最理想的结果。

## 3. 编写提示词的六个要点

### 3.1 设定角色与能力

我可以根据任务需要，告诉模型以什么身份完成任务。

```text
你是一名擅长Python教学的老师，能够使用简单的例子解释知识。
```

角色不是必须填写，但明确角色有助于模型选择合适的知识和表达方式。

### 3.2 明确核心任务

我要直接说明希望模型完成什么，避免只给出模糊的主题。

```text
请解释Python中的浅拷贝和深拷贝有什么区别。
```

### 3.3 拆分复杂任务

任务比较复杂时，我可以把它拆成多个步骤，让模型按照顺序处理。

```text
请按照下面的步骤回答：
1. 先解释浅拷贝。
2. 再解释深拷贝。
3. 使用表格对比两者。
4. 最后提供一个简单代码示例。
```

### 3.4 指定风格与语气

我可以说明希望使用什么表达方式，以及回答面向什么人。

```text
请使用简洁、口语化的语言，面向Python初学者解释，避免一次引入太多高级概念。
```

### 3.5 明确输出格式

如果我希望得到固定结构，应当提前说明输出格式。

```text
请严格按照下面的格式输出：
1. 概念
2. 主要区别
3. 对比表格
4. Python代码示例
```

明确输出格式有助于减少内容杂乱，也方便程序继续处理模型返回的数据。

### 3.6 提供输入输出示例

我可以给模型一个参考示例，让它模仿示例的结构或风格。这种做法也叫**少样本提示（Few-shot Prompting）**。

```text
示例输入：什么是列表？
示例输出：列表是Python中用于按顺序保存多个数据的容器。

现在请按照相同风格回答：什么是元组？
```

## 4. 可以直接套用的提示词模板

不是每次都必须填写所有部分，我可以根据任务复杂程度选择需要的内容。

```text
角色：
你是一名______。

任务：
请帮我完成______。

背景或输入：
______

执行步骤：
1. ______
2. ______
3. ______

要求与限制：
- 使用______风格。
- 面向______人群。
- 不要______。

输出格式：
请按照______格式输出。

参考示例：
______
```

## 5. 完整示例

```text
你是一名擅长Python教学的老师。

请向一名刚开始学习Python的学生解释装饰器。

要求：
1. 先用一句通俗的话说明装饰器的作用。
2. 再提供一个可以直接运行的简单代码示例。
3. 解释代码的执行过程。
4. 使用简洁、口语化的语言，不引入复杂框架。

请按照“概念、代码、执行过程、总结”的格式输出。
```

## 6. 提示词检查清单

- 是否明确描述了任务，而不只是提供一个模糊主题。
- 是否根据任务需要说明了角色、步骤、风格和限制。
- 是否指定了便于使用的输出格式。
- 是否在容易产生歧义时提供了示例。
- 是否根据模型的实际输出继续调整提示词。

> [!summary] 一句话理解
> 提示词告诉大模型“我要什么”，提示词工程则是不断调整表达方式，让大模型更稳定地给出我需要的结果。
